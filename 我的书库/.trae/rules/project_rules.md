# 知识库项目 · 开发与使用规则

> 本文件随「我的书库」文件夹走：在 TRAE 中打开「我的书库」文件夹作为工作区时自动加载生效。
> 工作区内本目录即书库根（含 书籍\、检索脚本\），规则内路径均相对本目录书写。

## 编码军规（第一条，违反即返工）
- 所有脚本与文档文件读写一律 `encoding='utf-8'`，禁止 GBK/ANSI。
- **唯一例外：`.bat` 批处理文件必须保存为 GBK（代码页 936）+ CRLF 换行，首行 `@echo off` 后紧跟 `chcp 936 >nul`**。bat 内禁止使用 GBK 无法编码字符（如 `✅`，用 `[OK]` 代替）。
- 所有路径拼接一律基于项目根目录（含 `路径配置.json` 的目录），用 `pathlib` 相对推算，**禁止绝对路径字面量**。
- 唯一入口配置文件：项目根 `路径配置.json`（含目录路径、`阈值`、`查询模式`）。所有脚本经 `common.load_config()` / `common.get_path()` 读取。

## 执行规则（TRAE 里让 AI 干活时必须遵守）
1. 完成任何文件改动后，先跑对应脚本的 `--自检` 再交付。
2. 检索知识库必须调用 `检索脚本\search_keyword.py`（内置 UTF-8 输出，无需设置 `PYTHONIOENCODING`）：
   - `--fetch "词"` 组合动作（**默认优先**）：一趟返回 块ID+页码+章名+行号+指纹+逐字原文；支持 `--书 "书名[,书名]"`、`--类 "分类"` 范围过滤，以及 `--速查` / `--完整` 档位覆盖（缺省读 `路径配置.json` 的 `查询模式`）；
   - `--query "词"` 关键词检索（支持 `--书`/`--类`、逗号分隔多词；输出带「⚠️ 弱命中」时须换词重查）；
   - `--locate "块ID"` 现场定位块；`--verify "块ID" "预期指纹"` 指纹比对纠偏；
   - 禁止直接用人工行号/硬编码行号；禁止跳过脚本直接整读原文.md。
3. 引用块内容必须带块 ID（如 `【0001·0007】`），否则视为无出处、不采信。
4. 查询词未直接命中时，允许用同义词换词重查，但必须明示"未直接命中"并列出已试检索词。
5. 知识库全部内容需经管线入库，禁止把外部文本直接塞进 `书籍\`。

## 检索协议（在 TRAE 对话内查询知识库时必须遵守）
1. **铁律**：原文必须逐字引用（不截断），禁止凭记忆转述；讲解与原文分开呈现；标签/摘要未命中 ≠ 原文没有，必须经过 n-gram 全文扫描后方可下结论。

## 检索路径（第0步改写 → 首轮单路快查 → 不中再翻摘要）
0. **查询改写（静默必做）**：先将口语问题改写为 3~6 个书面术语/原词/异名实词（禁用单字与整句原样检索；已有完整四字术语如「伤官见官」时写 `伤官见官,伤官克官`，勿额外拆成 `伤官,见官` 重复加权），逗号合并一次发出，不向用户展示改词过程。
1. **第 1 轮 · 单路快查（默认优先）**：锁定范围后（点名某书用 `--书 "书名"`；多本书合并为一次 `--书 "书A,书B"`，**禁止拆成多个 `--fetch` 并发**；点名类别先读《书目总索引.md》明示书目并用 `--类 "分类"`；均未点名先锁定唯一候选书，锁不定则一句反问，禁止全库漫游），直接执行 `检索脚本/search_keyword.py --fetch "词1,词2,..." --书 "..."`（或 `--类`）。`--fetch` 一趟返回 块ID+页码+章名+行号+指纹+逐字原文，首轮不并发读取《目录骨架.md》与《章节摘要》；无需设置环境变量（脚本内置 UTF-8）。只要榜单概览时才用 `--query`。
2. **第 2~3 轮 · 换词与目录/摘要兜底**：仅当第 1 轮未命中、输出带「⚠️ 弱命中」，或用户问全书框架/综述类问题时，再换同义词/上下位词重查并查阅《目录骨架.md》与《章节摘要/{章}.md》定位（无命令行时直接走索引→骨架→摘要→按块读取原文），最多 3 轮；仍未命中则诚实告知并列出已试检索词。
3. **效率与边界**：多词必须逗号合并一次 `--query/--fetch`；**`--fetch` 已现场扫描原文并附带实时行号与指纹，禁止对 `--fetch` 返回的块再重复跑 `--verify`**（`--verify` 仅用于手工查文件或旧锚点表拿到的块 ID）；读原文按行号区间只读命中块，禁整读 `原文.md`。**章节摘要、块标签及速查「---【预览】」行仅作导航定位，严禁当作原文引用**；`--locate` 报已退休时如实应答。

## 输出格式与双模式联动
- **速查模式**（`--fetch` 首行标明「当前模式：速查」时，**严禁套用完整四段式，不单列 📖定位清单、不写长篇分点讲解与额外 📝总结**，保持极简速读）：
  - **💡 核心结论**：2~4 句直白人话直接回答核心问题（≤150 字）；
  - **📜 关键原文**：仅引 **1~2 段**最切题的逐字完整原文（不截断；每段前标《书名》+ 章名 + 印刷页码、段末以【块 ID】收口，跨书逐段标全）；
  - **末尾固定提示**：「当前为速查模式，如需查看其余命中原文或完整展开讲解，直接回复“展开完整版”即可。」用户要求展开时，用 `--完整` 补全其余原文并按下方完整模式作答。
- **完整模式**（未标速查，或用户要求展开完整版时）：
  - **📖 定位**：《书名》+ 章名 + 印刷页码（降级块标 `PDF.页序`，非分页书为顺序号）+ 【块 ID】
  - **📜 原文**：逐字完整引用（不截断）；每段前标《书名》+印刷页码、段末以【块 ID】收口，跨多本书逐段标全（禁止只写块 ID）
  - **🧠 讲解**：结合上下文，与原文分开呈现
  - **📝 总结**：3~5 点要点归纳
  - 单次最多引用 5 块；命中更多时声明「还有 N 处命中，是否继续」。

2. 块 ID 是身份证不是顺序号，数字跳跃属正常（书籍更新后老块退休、新块尾部领号）；阅读顺序以目录骨架/原文物理顺序为准。
3. **生效宣告**：每次会话首次按本协议作答时，回答第一行固定输出 `🔎 已按知识库检索协议检索`，同会话后续回答不重复；**未走检索流程的回答一律不得带此标记**（无标记/无块 ID 的回答＝凭印象作答，可打回要求按协议重查）。

## 管线顺序（不可跳卡）
入库：`extract.py` → `quality_check.py`（红灯即停）→ `clean_split.py` → `build_index.py` → 移入已入库。
标注：`verify_needles.py`（密文自检）→ `annotate_pack.py --生成` → 外部 AI 回填 → `annotate_pack.py --导回` → 术语自动配对。
评测：`eval_gen.py --判分 <回答文件>`（回答文件每行 `| 题号 | 回答 |`）。

## 红线
- 原文层逐字转录、块不可改：已出生的块内容零改动；书籍更新只允许经 update_book 整块增/删/换（老块退休+新块领号），禁止改写既有块内容；密文验证等处理用副本，验证前后比对文件哈希自证。
- 退出码约定：0=成功/绿灯，1=失败/红灯，2=部分成功。脚本异常不弹栈，写 `报告\`（项目根）对应报告。
