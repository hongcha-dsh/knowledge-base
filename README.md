# 知识库 Knowledge Base

把书籍资料变成**可被 AI 逐字引用**的本地知识库。

`docx / PDF / txt / md / xlsx` → 入库管线 → **逐字转录的原文 + 块 ID + 倒排索引** → AI 按协议检索、引用原文并讲解。

纯 Python + Tkinter，零联网依赖（只有扫描版 PDF 的 OCR 会调用 MinerU 云端 API）。

> A local book-to-knowledge-base system. It ingests `docx / PDF / txt / md / xlsx` into a **verbatim transcript with stable block IDs and an inverted index**, so an AI can retrieve passages and cite the source text line by line — every quote traceable to a specific book, page and block ID.

---

## 为什么这样设计

让 AI 讲书，最大的问题是**没有出处、随口编**。这个项目的核心是一条硬约束链：

| 约束 | 做法 |
|---|---|
| **原文逐字转录** | `原文.md` 与书籍内容逐字一致，只做物理行切分（≤80 字/行），一字不改 |
| **AI 生成内容物理隔离** | 摘要、标签、术语只写进索引层，**绝不混入原文层** |
| **块 ID 出生即定** | 每段有唯一编号（如 `0004·0123`），引用可回溯、可验证；编号只增不重排 |
| **指纹校验** | 每块带指纹，AI 回填错位会被机械闸直接拒绝 |
| **处理用副本** | 任何加工都在副本上做，前后哈希比对自证原文未被改动 |
| **更新不重排** | 书出修订版时只换变化的块，未变段落编号与已有标注原样保留，改动可对账、可回滚 |

结果是：AI 回答里每段引用都能定位到**具体书籍 + 印刷页码 + 块 ID**，你一眼就能判断它到底查没查书。

## 功能特性

### 入库管线
- **五步流水线**：提取 → 质量关卡 → 清洗分块 → 建索引 → 移入已入库
- **五种输入格式**：docx / pdf（文本层或 OCR）/ txt / md / xlsx，类型自动探测，无需手工指定
- **扫描版 PDF 自动走 OCR**：按页路由（文本页取文本层、扫描页走 OCR）；超过云端 200 页上限的 PDF 自动分卷上传再合并，无需手工拆书
- **章节识别**：结构信号（MinerU `text_level` / docx 大纲 / md 的 `#`）→ 章级过滤 → 无信号时启发式兜底；不套 `第X章` 命名法的书可由标注 AI 一次性生成书级结构配置
- **页码拟合**：纯数字 / 装饰数字 / 罗马数字 / `第N页` / `Page N` / `N·M` / 中文数字多格式支持；无锚点时**诚实降级**为 `PDF.页序`，不硬猜
- **三道闸门**：字符 diff、跨页重复行、内容型特判；黄灯告警不阻塞（退出码 2）
- **质量关卡**：平均每页字数、乱码率、不可辨识字符密度，红灯即停
- **隔离区**：页眉页脚页号不删除，单独归档可复核回收
- **书籍更新**：出修订版时增量更新而非整书重入——块 ID 不变，未变段落标注原样保留，变化章自动进入待重标；双路径互证对账，红灯自动回滚
- **更新与写入安全**：更新过的书再重建索引只重建搜索、不重排正文；正文与索引写盘用原子替换；入库 / 标注 / 重建 / 更新 / 删除等写库任务互斥，同一时刻只允许一个

### 控制台（Tkinter）
- 单主页（书库）+ 按需弹窗的信息架构，浅色主题，色板令牌集中管理
- 表格化书库：书名 / 分类（可双击行内编辑）/ 标注进度 / 状态
- 右上角**查询模式开关**：速查 / 完整 一键切换并自动记住（写进配置文件）
- 底部常驻全局任务状态条：后台任务进度 + 已用时秒表，**关窗不丢任务**
- 后台任务全程不冻结界面，可自由操作

### 标注与回填
- **API 自动标注**：调用任意 OpenAI 兼容接口，多路并发（默认 8 路），机械闸自动质量把关，不合格自动打回重试（至多 3 次）
- **外发标注**：生成任务包交给任意 AI 填写，支持 AI 自动回填或人工回填
- **术语自动配对**：回填后自动把异名整理成「主词条 + 别名」写入术语表，检索时输入任意叫法都能命中
- **幂等**：`.done` 为唯一状态源，重复导入自动跳过

### 检索
- 四种模式：关键词检索（支持逗号分隔多词）、组合取原文（一趟拿齐块 ID + 页码 + 章名 + 行号 + 指纹 + 逐字原文）、现场定位、指纹校验
- **按书 / 按类检索**：`--书`、`--类` 限定范围，多本书可一次合并查询
- **速查 / 完整双档**：`--fetch` 默认读配置里的档位，速查给前 3 块全文 + 其余命中头行预览，完整给前 5 块全文
- 自动简繁归一 + 术语表扩展；块标签导航节降权，避免导航词挤占原文
- 同页相似块去重防「车轱辘块」霸榜，排序确定性化消除抖动；弱命中主动提示
- 索引损坏 / 倒排表缺失时**显式报错退出**，不静默漏书；已退休的块 ID 会说明作废日期与后继块

### 评测
- 密文自检（埋针验证，临时副本验完即删）
- 检索命中率评测尺：top5 / top10 / MRR，支持**纯内容 / 含题干**两种口径，另有真实口语提问盲测集（`--集 真实`）；检索改动前后可报数对比

## 快速开始

### 1. 获取代码

```bash
git clone https://github.com/hongcha-dsh/knowledge-base.git
cd knowledge-base
```

### 2. 建配置文件

把 `路径配置.example.json` 复制一份，**改名为 `路径配置.json`**，放在项目根目录：

```bash
copy 路径配置.example.json 路径配置.json
```

> 这个文件是项目的唯一起点：所有脚本靠它定位项目根和各个目录。缺了会直接报错退出。

### 3. 准备书库目录

仓库里已经带了 `我的书库\`（只有检索协议与检索脚本）；待入库 / 已入库 / 输出 / 报告 / 书籍 等目录会在首次使用时自动创建。`资料预处理\书规则\` 只在需要给某本书做特调时手工建（做法见「验证书是否健康」一节）。

### 4. 启动

双击项目根目录的 **`启动控制台.vbs`**。

启动器会自检 Python 与依赖——**缺依赖会自动弹窗安装，装完自动打开控制台**，不会出现黑窗口。

也可以手动装依赖：

```bash
pip install -r 资料预处理/控制台/requirements.txt
```

## 配置说明

配置文件 `路径配置.json` 的 `api` 节：

### 查询模式（速查 / 完整）

```json
"查询模式": "速查"
```

`速查` 与 `完整` 只影响 `--fetch` 的默认档位（返回几段原文、要不要预览其余命中）。一般不用手改：控制台窗口右上角有【查询模式：速查 / 完整】开关，点一下即切换并自动保存。

### MinerU Token（仅扫描版 PDF 需要）

只有**图片版 PDF（没有文字层的扫描书）**才需要联网 OCR：

- 纯文字 docx / txt / md / xlsx / 带文字层的 PDF → **不用配，直接入库**
- 要 OCR → 到 [mineru.net](https://mineru.net/apiManage/docs) 注册登录 → `api` → `api管理` → `创建 token` → 复制

填进控制台「⚙ 设置 → ① MinerU 区」，点**保存 Token**，再点**测试连通性**确认全部 `[OK]`。

> 未配置时，扫描版 PDF 走不了 OCR 通道（离线报错、不消耗额度），入库列表里这类文件会标「未配 Token」。

### 标注 AI（可选，用 API 自动标注才需要）

填 OpenAI 兼容接口的三要素：

```json
"annotate_api": {
  "base_url": "https://ark.cn-beijing.volces.com/api/v3",
  "api_key": "你的密钥",
  "model": "doubao-pro-32k"
}
```

火山方舟、DeepSeek 等服务通用。两个可选项：

- **附加参数**：JSON 原样透传给服务商。例如用 DeepSeek 想关掉思考模式省时省钱：`{"thinking": {"type": "disabled"}}`（参数名以服务商文档为准，填错会调用报错）
- **并发**：同时处理几个任务包，默认 `8`；填 `1` 最稳但最慢

不配也能用**外发标注**（把任务包发给你常用的 AI 填）。

### 环境变量（优先级高于配置文件）

| 变量 | 作用 |
|---|---|
| `MINERU_API_TOKEN` | 覆盖 MinerU Token |
| `ANNOTATE_API_KEY` | 覆盖标注 AI 密钥 |

> 把密钥放环境变量、配置文件里留空，可以避免误把密钥提交进 git。

## 使用流程

### 入库一本书

1. 主页点 **【＋ 添加书籍】**（也可以先把文件丢进 `资料预处理\待入库\`）
2. 类型自动探测并默认全选，点 **【开始入库】** —— 支持多选批量
3. 进度实时可见；**窗口可以直接关掉，任务照跑**，进度看主窗口底部状态条
4. 完成后自动做一次密文验证，结果区给红绿灯汇总

文件名建议用 `编号--书名--备注.docx`。

### 给书做标注（可选，做了检索更准）

**方式一：API 自动标注（推荐）**——配好标注 AI 后选中书 → 【开始标注】→ 全程自动，跑完术语自动配对。

**方式二：外发标注**——展开高级区 → 【① 生成任务包】（自动打开文件夹并复制好引导提示词）→ 发给你常用的 AI 填写 → 【② 导入标注】。用纯对话类 AI 时注意：文件名必须一模一样、编码 UTF-8、扩展名 `.md`、表格竖线用半角 `|`。

**进度**看主页「标注」列（未开始 / 进行中 x/n / 已完成）。

### 验证书是否健康

主页选中书 → 高级区 → **【重建索引（含自动验证）】**——重建完自动再验一次。更新过的书会显示「正文受更新保护」，只重建搜索、不重排正文。

状态显示「需复查」时，选中该行点主按钮 **【查看问题】**，把日志里那句话复制发给 AI 排查即可。

> 报告目录 `报告\` 是「**没修好的问题**」清单：全绿时不产生报告，修好重跑转绿，旧报告自动消失。

排盘类书若想让盘独立成块、也能标注（豁免图表块收纳），手工建 `资料预处理\书规则\{书名}.json`（文件名＝书名，UTF-8），内容写 `{"豁免图表块收纳": true}`，再点一次【重建索引】即生效；想关掉把 `true` 改成 `false` 或删掉该文件再重建。

### 调整回答档位（速查 / 完整）

控制台右上角【查询模式：速查 / 完整】点一下即切换，之后 AI 按对应档位作答：

- **速查**：2~4 句直白结论 + 1~2 段最切题的逐字原文，废话少、出答案快；想细看再回「展开完整版」
- **完整**：最多 5 段逐字原文 + 完整讲解

也可以在命令里临时指定 `--速查` / `--完整` 覆盖。

### 书出了修订版

主页选中书 → **【书籍更新】** → 选新版文件 → 先看比对统计（保留 / 修订 / 删除 / 新增各多少）→ 确认后后台执行，自动备份 + 双路径互证对账，**校验不通过会自动恢复原样**。未变的段落编号和标注都不动；被删改的旧块会登记「退休档案」，以后按老编号查会明确提示作废并给出后继块。

### 删除一本书

选中 → **【删除书籍】**。原件不会被删，会自动移回待入库；评测集里这本书的题目一并清理、其余题号自动接续。

> 写库任务（入库 / 标注 / 重建 / 更新 / 删除）不能同时跑：正在跑一个时再点别的会被提示「另一个写库任务正在进行中」，本次操作不会开始。

## 命令行用法

脚本位于 `我的书库/检索脚本/`。**脚本已内置 UTF-8 输出**，不需要再设 `PYTHONIOENCODING` 之类环境变量。

### `search_keyword.py` —— 四种模式

```bash
# 1. 组合动作（推荐）：一次返回 块ID + 行号 + 章名 + 指纹 + 原文逐字全文
python search_keyword.py --fetch "排龙诀"
python search_keyword.py --fetch "排龙诀" --书 "书名"       # 限定一本书
python search_keyword.py --fetch "排龙诀,挨星" --书 "书A,书B"        # 多本合并一次查
python search_keyword.py --fetch "排龙诀" --类 "分类名"               # 限定一个分类
python search_keyword.py --fetch "排龙诀" --速查                    # 临时用速查档
python search_keyword.py --fetch "排龙诀" --完整                    # 临时用完整档

# 2. 关键词检索（只要榜单概览时用；多词用逗号合并）
python search_keyword.py --query "排龙诀"
python search_keyword.py --query "排龙诀,挨星" --书 "书名"

# 3. 现场定位块（输出附带 PDF 页序）
python search_keyword.py --locate "0004·0123"

# 4. 指纹比对纠偏
python search_keyword.py --verify "0004·0123" "sha256:...."
```

`--fetch` 是给 AI 用的高效模式：把「查询 + 定位 + 取原文」合并成一趟。档位由 `路径配置.json` 的 `查询模式` 决定，也可用 `--速查` / `--完整` 临时覆盖：

- **速查**：前 3 块逐字全文 + 前 5 条命中头行预览（够回答，又不刷屏）
- **完整**：前 5 块逐字全文

### `eval_recall.py` —— 检索命中率评测尺

```bash
python eval_recall.py                    # 对评测集跑 top5 / top10 命中率 + MRR（纯内容 / 含题干双口径）
python eval_recall.py --集 真实          # 真实口语提问盲测集（对照「关导航 vs 含块标签导航」）
python eval_recall.py --自检             # 自检
```

改动检索逻辑前后跑一次报数对比，可以客观判断是变好还是变差（旧题块 ID 失效会自动剔除并计数）。

## 接入 AI 对话

仓库内已包含一份完整的检索协议：**`我的书库/.trae/rules/project_rules.md`**。

在 [TRAE](https://www.trae.ai/) 中把 **`我的书库`** 文件夹作为工作区打开，这份协议会自动加载生效。它约定了「AI 真查了书」的两个可验证标志：

1. **生效宣告** —— 每次会话首次按协议作答，回答第一行固定输出 `🔎 已按知识库检索协议检索`（同会话不重复，没走检索流程的回答不许带这个标记）
2. **块 ID 收口** —— 引用的每段原文前面标 `《书名》+ 印刷页码`，段末以 `【块 ID】` 收口

两者缺一，就说明 AI 没查书、在凭印象编，可以直接打回要求「按检索协议检索后再回答」。

协议同时规定了检索路径（先静默改写查询词 → 首轮单路 `--fetch` 快查 → 不中再翻目录骨架与章节摘要兜底，最多 3 轮）、输出档位（速查两段式 / 完整四段式）、每次最多引用 5 块、标注回环铁律（标签索引没命中 ≠ 原文没有，必须回退全文扫描才能下结论）等口径。

> 如果你用别的 AI 工具（非 TRAE），把这份协议文本作为系统提示词或工作区规则交给它即可，效果相同。

## 常见问题

**Q：双击启动没反应 / 提示找不到 Python？**
装 Python 3.12+ 时务必勾选 `Add to PATH`，然后重新双击 `启动控制台.vbs`（缺依赖它会自己弹窗安装）。

**Q：入库卡在「质量关卡红灯」？**
资料质量不过关（乱码多 / 空页多 / OCR 不可辨识字符超标）。到 `报告\` 里找这本书的失败清单，把失败页用别的工具转成文字存成 `.txt` 再走文本通道入库。

**Q：扫描版 PDF 入库失败、提示 OCR 相关错误？**
先检查 MinerU Token 是否已填并通过「测试连通性」。没配 Token 时扫描 PDF 走不了 OCR 通道（离线报错、不消耗额度）。

**Q：导入任务包失败，提示「列数错误」？**
① 用的是旧版任务包（现在模板是 5 列，多了「指纹」列），请重新生成；② 表格竖线打成了全角 `｜`，全部换成半角 `|`。

**Q：提示「指纹不符，疑似标注错位」？**
任务包的「指纹」列被改动了。这一列必须保持生成时的原样，只填标签 / 术语 / 别名三列。

**Q：查询结果对不上原文？**
选中该书 → 高级区 →【重建索引（含自动验证）】。

**Q：速查 / 完整切了没生效？**
档位存在 `路径配置.json` 的 `查询模式`，切换后新发起的检索才按新档位走；命令里显式传 `--速查` / `--完整` 优先级更高。

**Q：提示「另一个写库任务正在进行中」？**
同一时刻只允许一个写库任务（入库 / 标注 / 重建 / 更新 / 删除），等当前任务结束再点，或点状态条【查看日志】看它在跑什么。

**Q：整个项目想搬到别的文件夹或别的电脑？**
直接整个文件夹复制走即可（路径自动适配，中文路径也没问题），到新位置双击 `启动控制台.vbs`。
